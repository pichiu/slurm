# Slurm 階層資源 (HRES) 排程指南

## TL;DR

階層資源 (HRES) 於 Slurm 25.05 新增（Beta 狀態）。允許定義類似授權的資源作為獨立階層拓撲的一部分並關聯到特定節點。三種規劃模式：MODE_1（任一層級滿足即可）、MODE_2（所有重疊層級都需滿足）、MODE_3（按節點消耗並向上層累加，適用於電力等資源）。透過 resources.yaml 設定。

---

## 翻譯

### 概觀

階層資源 (HRES) 於 Slurm 25.05 新增，處於 **Beta** 狀態。在 beta 期間，設定檔格式和此功能的其他方面可能在未來版本中發生重大變更，需要進行重大修改以避免錯誤。使用此 beta 功能的站點在[升級](upgrades.md)時應特別注意 RELEASE_NOTES 和 CHANGELOGs 中的變更說明。

階層資源允許將類似[授權](licenses.md)的資源定義為獨立階層拓撲的一部分，並關聯到特定節點。作業可以請求該資源的任何整數數量。可以在設定中（在 [resources.yaml](resources.yaml.html) 檔案中）定義多個資源，並使用獨立定義的階層。

雖然這些階層拓撲與[網路拓撲](topology.md)有一些相似之處，但每個的定義是完全分開的。

---

### 規劃模式

提供三種資源規劃模式。在任一情況下，可以將層級定義為零個或無限個（`count: -1`）資源，其影響取決於使用的模式。

---

#### 模式 1 (MODE_1)

在 **模式 1** 中，只需要與作業分配重疊的**一個層級**有足夠的資源。在許多情況下只需要單一層級。但是，如果偏好在資源使用位置上有一些額外的彈性，可以定義多個層級。

**零計數**：
- 該資源計數為零的層級對排程沒有影響
- 由於該層級永遠不會滿足請求，它永遠不會改變計算出的有資格運行給定作業的節點列表
- 語義上等同於移除該層級定義

**無限計數**：
- 該資源計數為無限的層級將始終允許新作業分配成功
- 除非受到其他需求阻止，否則作業將能夠立即執行

**範例**：
考慮下方範例 resources.yaml 檔案中定義的 **natural** 資源。請求此資源並被分配 `node[01-04]` 的作業將從可用於 `node[01-16]` 的 100 個資源池中提取。在更高層級（`node[01-32]`）指定的 50 個可以額外分配給每組 16 個節點中指定的資源。即每組 16 個節點各有 100 個，另外 50 個可用於任何一組，總共 250 個此資源。

---

#### 模式 2 (MODE_2)

在 **模式 2** 中，與作業分配重疊的**所有層級**都必須有足夠的資源可用。請注意，如果較高層級沒有提供足夠的資源，可能會發生排程停滯。

**零計數**：
- 該資源計數為零的層級對排程有重大影響
- 該層級下的所有節點永遠無法滿足分配限制
- 這可用於將該資源標記為叢集特定部分不可用（例如用於硬體維護），而無需更改個別較低層級的資源計數

**無限計數**：
- 該資源計數為無限的層級對排程沒有影響
- 由於該層級始終滿足請求，它永遠不會限制執行
- 語義上等同於移除該層級定義

**範例**：
考慮下方範例 resources.yaml 檔案中定義的 **flat** 資源。請求此資源並被分配 `node[01-04]` 的作業將從包含這些節點的所有層級提取。因此它會從 `node[01-08]` 可用的 12 個中提取，從 `node[01-16]` 可用的 16 個中提取，以及從 `node[01-32]` 可用的 24 個中提取。由於最高層級只有 24 個，這是可以分配的最大值，即使較低層級有更大的總數。此範例允許固定的資源集合在使用位置上有一些彈性。

---

#### 模式 3 (MODE_3)

在 **模式 3** 中，資源按節點分配，總消耗從最細粒度的層級計算並向上累加到更高層級。此模式專門設計用於電力等可消耗資源，其中較高層級（例如叢集範圍）的總使用量是其組成部分（例如機箱層級，然後是累加多個機箱的機架層級，然後是資料中心行）的使用量總和。

排程器確保階層中每個層級的總累加資源不超過該層級定義的計數。

**重要注意事項**：在 **模式 3** 下定義的層級必須能夠表示為**有根均勻深度樹**。

**範例**：
考慮下方範例 resources.yaml 檔案中定義的 **power** 資源。請求 1000 個 **power** 資源並被分配 `node[01-16]` 的作業將從包含這些節點的所有層級提取。因此它會從 `node[01-08]` 提取 8000，從 `node[09-16]` 提取 8000，從 `node[01-16]` 提取 16000，以及從 `node[01-32]` 提取 16000。

---

### 限制

- 資源計數無法動態變更；所有變更必須透過 **resources.yaml** 進行並透過重新啟動或重新設定套用
- 不支援動態節點
- 此實作處於 **beta** 狀態（請參閱概觀）
- 透過階層資源設定定義的資源名稱不得與任何叢集授權衝突

---

### 使用範例

在 **resources.yaml** 中定義資源階層後，您可以使用已用於授權的語法與這些資源互動：

**查看 HRES**：
```bash
scontrol show license
```

**預約 HRES**：
```bash
scontrol create reservation account=root \
  licenses=natural(node[01-016]):30,flat(node[09-12]):4,flat(node[29-32]):2
```

注意：必須為每個預約的 HRES 指定層級，透過該層級可用的節點列表識別。

**在作業中請求 HRES**：
```bash
sbatch --license=flat:2,natural:1 my_script.sh
```

### resources.yaml 範例

```yaml
---
- resource: flat
  mode: MODE_2
  layers:
    - nodes:                    # 最高層級
        - "node[01-32]"
      count: 24
    - nodes:                    # 中間層級
        - "node[01-16]"
      count: 16
    - nodes:
        - "node[17-32]"
      count: 16
    - nodes:                    # 最低層級
        - "node[01-08]"
      count: 12
    - nodes:
        - "node[09-16]"
      count: 12
    - nodes:
        - "node[17-24]"
      count: 12
    - nodes:
        - "node[25-32]"
      count: 12

- resource: natural
  mode: MODE_1
  layers:
    - nodes:                    # 最高層級
        - "node[01-32]"
      count: 50
    - nodes:                    # 最低層級
        - "node[01-16]"
      count: 100
    - nodes:
        - "node[17-32]"
      count: 100

- resource: power
  mode: MODE_3
  topology: blok1
  variables:
    - name: full_node
      value: 1000
    - name: full_gpu_node
      value: 2000
  layers:
    - nodes:
        - "node[01-08]"
      count: 40000
      base:
        - name: storage
          value: 5000
    - nodes:
        - "node[17-24]"
      count: 40000
    - nodes:
        - "node[09-16]"
      count: 40000
    - nodes:
        - "node[25-32]"
      count: 40000
    - nodes:
        - "node[01-16]"
      count: 60000
      base:
        - name: network1
          value: 3000
    - nodes:
        - "node[17-32]"
      count: 80000
      base:
        - name: network2
          value: 2000
    - nodes:
        - "node[01-32]"
      count: 130000
      base:
        - name: acUnit1
          value: 10000
        - name: acUnit2
          value: 8000
```

## 說明

### 模式比較

| 模式 | 資源需求 | 適用場景 |
|------|----------|----------|
| MODE_1 | 任一重疊層級滿足 | 彈性資源池 |
| MODE_2 | 所有重疊層級都需滿足 | 嚴格限制 |
| MODE_3 | 按節點消耗向上累加 | 電力等可加總資源 |

### 階層結構圖

```
MODE_1 (natural):
┌─────────────────────────────────┐
│    node[01-32]: 50 (額外可用)    │
├─────────────┬───────────────────┤
│ node[01-16] │    node[17-32]    │
│    : 100    │       : 100       │
└─────────────┴───────────────────┘
  總共可用: 100 + 50 = 150（每組）

MODE_2 (flat):
┌─────────────────────────────────┐
│       node[01-32]: 24           │ ← 最大限制
├─────────────┬───────────────────┤
│ node[01-16] │    node[17-32]    │
│    : 16     │       : 16        │
├──────┬──────┼──────┬────────────┤
│01-08 │09-16 │17-24 │   25-32    │
│ :12  │ :12  │ :12  │    :12     │
└──────┴──────┴──────┴────────────┘
  每個作業需滿足所有重疊層級

MODE_3 (power):
┌─────────────────────────────────┐
│     node[01-32]: 130000         │ ← 累加限制
│   (+ acUnit1 + acUnit2)         │
├─────────────┬───────────────────┤
│ node[01-16] │    node[17-32]    │
│   : 60000   │      : 80000      │
│(+ network1) │   (+ network2)    │
├──────┬──────┼──────┬────────────┤
│01-08 │09-16 │17-24 │   25-32    │
│40000 │40000 │40000 │   40000    │
└──────┴──────┴──────┴────────────┘
  消耗從節點向上累加
```

## 實務範例

### 基本 resources.yaml 設定

```yaml
# /etc/slurm/resources.yaml
---
# 簡單的授權類資源
- resource: software_license
  mode: MODE_1
  layers:
    - nodes:
        - "node[01-100]"
      count: 50

# 電力管理資源
- resource: power
  mode: MODE_3
  layers:
    - nodes:
        - "node[01-50]"
      count: 100000
    - nodes:
        - "node[51-100]"
      count: 100000
    - nodes:
        - "node[01-100]"
      count: 180000
```

### slurm.conf 設定

```
# 啟用階層資源
# 注意：resources.yaml 需放在 Slurm 設定目錄
```

### 作業請求範例

```bash
# 請求軟體授權
sbatch --license=software_license:5 job.sh

# 請求電力資源
sbatch --license=power:2000 gpu_job.sh
```

### 預約資源

```bash
# 為維護預約特定層級的資源
scontrol create reservation user=admin \
  starttime=now duration=2:00:00 \
  nodes=node[01-10] \
  licenses=power(node[01-50]):50000
```

## 常見錯誤與建議

### 常見錯誤

| 錯誤 | 正確做法 |
|------|----------|
| 在生產環境使用 beta 功能 | 了解 beta 狀態的風險 |
| 資源名稱與授權衝突 | 使用唯一的資源名稱 |
| MODE_3 非均勻深度 | 確保樹結構均勻 |
| 動態變更計數 | 透過 resources.yaml 和重啟變更 |

### 建議

1. **謹慎使用**：
   - 這是 beta 功能，可能有重大變更
   - 在非生產環境測試
   - 仔細閱讀升級說明

2. **模式選擇**：
   - MODE_1：需要彈性的資源池
   - MODE_2：需要嚴格限制的場景
   - MODE_3：電力等可累加資源

3. **電力管理**：
   - 使用 MODE_3 進行電力預算
   - 設定 base 值表示固定消耗
   - 考慮冷卻等基礎設施需求

## 快速參考

### 模式概要

| 模式 | 說明 |
|------|------|
| MODE_1 | 任一層級滿足即可 |
| MODE_2 | 所有層級都需滿足 |
| MODE_3 | 向上累加消耗 |

### 特殊計數值

| 值 | MODE_1 | MODE_2 | MODE_3 |
|----|--------|--------|--------|
| 0 | 無影響 | 阻止分配 | N/A |
| -1 (無限) | 總是允許 | 無影響 | N/A |
